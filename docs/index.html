What it does

  1. Encrypted vault

    Entries live in a SQLCipher database; attachments are stored as separately encrypted files. Keys are derived with Argon2id and wrapped in LUKS-style key slots — changing your passphrase never re-encrypts your diary.

  2. Recovery key

    A randomly generated key, shown once at setup, lets you back in if the passphrase is forgotten. If you lose both, the diary cannot be recovered - by design

  3. Markdown, always

    Entries are written in Markdown and stored in the encrypted vault. No proprietary format: export everything to a folder of .md files in one click: the app can also verify, export, or rekey a vault.

  4. Your choice of location

    The vault is an ordinary folder: keep it on an internal disk, an external drive, or a mounted encrypted disk image.

  5. Encrypted full-text search

    Search runs inside the encrypted database. Nothing is indexed in plaintext, anywhere.

  6. Auto-lock

    The vault locks when idle, sleep, screen lock - and the keys are wiped from memory.

How it protects your data

The Rust core owns all keys, all file access, and all cryptography; the interface never holds a decryption key or touches vault internals directly. Encryption protects your diary at rest.

Take it home

  • macOS .dmg, ad-hoc signed — Gatekeeper blocks it on first open: right-click → Open, or build from source
  • Ubuntu .deb package — installs directly
  • Windows per-user installer, unsigned — SmartScreen will warn: More info → Run anyway, or build from source

On macOS and Windows, building from source skips the warnings entirely. Every release ships SHA256SUMS with a minisign signature, and the source builds from a tag — rebuilding is the trust anchor.
